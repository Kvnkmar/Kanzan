API Quickstart

A guided tour of the CRM REST API for tenant admins, integrators, and curious developers.

What is the CRM API?

CRM exposes a versioned REST API under /api/v1/ that mirrors everything you can do in the web UI: create and update tickets, manage contacts and companies, search the knowledge base, upload attachments, place VoIP calls, subscribe to webhooks, and more. Every endpoint is multi-tenant aware — your API key is scoped to a single tenant and inherits the permissions of a role you pick when minting it.

The full machine-readable contract is published as an OpenAPI 3.0 spec at /api/schema/, and an interactive Swagger UI is hosted at /api/docs/. This page is a curated walkthrough; the Swagger UI is the authoritative endpoint list.

Get an API key

Ask your tenant admin to mint one at Settings → Developer & Integrations → API Keys (admin-only). If you are an admin, open API Keys settings.

Keys look like kz_live_<your-tenant>_<random>. The full secret is shown once at creation — save it immediately to a password manager or your integration's secret store.

Make your first call

Here's the same request — list the first page of tickets — in three flavours. Replace kz_live_<your-tenant>_... with your actual key. 

curl -H "Authorization: Api-Key kz_live_<your-tenant>_..." \
     -H "Accept: application/json" \
     {{ request.scheme }}://{{ request.get_host }}/api/v1/tickets/tickets/?page=1
import requests

BASE = "{{ request.scheme }}://{{ request.get_host }}"
API_KEY = "kz_live_<your-tenant>_..."

resp = requests.get(
    f"{BASE}/api/v1/tickets/tickets/",
    headers={"Authorization": f"Api-Key {API_KEY}"},
    params={"page": 1},
)
resp.raise_for_status()
print(resp.json()["results"][0])
const BASE = "{{ request.scheme }}://{{ request.get_host }}";
const API_KEY = "kz_live_<your-tenant>_...";

const resp = await fetch(`${BASE}/api/v1/tickets/tickets/?page=1`, {
  headers: { "Authorization": `Api-Key ${API_KEY}` },
});
const data = await resp.json();
console.log(data.results[0]);

Common workflows

1. List open tickets assigned to a specific agent

Filter the tickets endpoint by assignee (UUID) and sort newest first.

curl -H "Authorization: Api-Key kz_live_<your-tenant>_..." \
     "{{ request.scheme }}://{{ request.get_host }}/api/v1/tickets/tickets/?assignee=<agent-uuid>&ordering=-created_at"

2. Create a ticket

POST a JSON body with the required fields. The response is HTTP 201 Created with the new ticket's id.

import requests

BASE = "{{ request.scheme }}://{{ request.get_host }}"
API_KEY = "kz_live_<your-tenant>_..."

resp = requests.post(
    f"{BASE}/api/v1/tickets/tickets/",
    headers={
        "Authorization": f"Api-Key {API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "subject": "Printer is offline on floor 3",
        "description": "User reports the HP LaserJet won't respond.",
        "priority": "high",
    },
)
assert resp.status_code == 201
print("Created ticket:", resp.json()["id"])

3. Add a comment to a ticket

Comments are polymorphic (a GenericForeignKey in Django), so you must specify both the content_type (as app_label.model) and the object_id. Send JSON — explicit Content-Type header required. 

curl -X POST \
     -H "Authorization: Api-Key kz_live_<your-tenant>_..." \
     -H "Content-Type: application/json" \
     -d '{
       "content_type": "tickets.ticket",
       "object_id": "<ticket-uuid>",
       "body": "Replaced the toner cartridge — please retry.",
       "is_internal": false
     }' \
     {{ request.scheme }}://{{ request.get_host }}/api/v1/comments/comments/

4. Upload an attachment

Attachments are also polymorphic. Send multipart/form-data with the file plus the target's content_type and object_id. Maximum upload size is 25 MB. 

curl -X POST \
     -H "Authorization: Api-Key kz_live_<your-tenant>_..." \
     -F "file=@path/to/file.pdf" \
     -F "content_type=tickets.ticket" \
     -F "object_id=<ticket-uuid>" \
     {{ request.scheme }}://{{ request.get_host }}/api/v1/attachments/

5. Search the knowledge base

Full-text search across published knowledge-base articles.

const BASE = "{{ request.scheme }}://{{ request.get_host }}";
const API_KEY = "kz_live_<your-tenant>_...";

const url = new URL(`${BASE}/api/v1/knowledge/search/`);
url.searchParams.set("q", "vpn troubleshooting");

const resp = await fetch(url, {
  headers: { "Authorization": `Api-Key ${API_KEY}` },
});
const data = await resp.json();
console.log(`Found ${data.results.length} articles`);

6. Subscribe to webhooks

Register a webhook that CRM will POST to whenever the listed events fire. Pick a secret known only to you and CRM — it's used to sign every payload. 

import requests

BASE = "{{ request.scheme }}://{{ request.get_host }}"
API_KEY = "kz_live_<your-tenant>_..."

resp = requests.post(
    f"{BASE}/api/v1/tickets/webhooks/",
    headers={
        "Authorization": f"Api-Key {API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "name": "Zapier ticket sync",
        "url": "https://hooks.example.com/crm/tickets",
        "events": ["ticket.created", "ticket.updated"],
        "secret": "a-long-random-string-known-only-to-you",
        "is_active": True,
    },
)
resp.raise_for_status()
print("Webhook id:", resp.json()["id"])

Verify the HMAC signature on your receiver. CRM signs every payload with HMAC-SHA256 of the raw body, sent in the X-Webhook-Signature header as sha256=<hex>: 

import hmac
import hashlib

def verify_webhook(raw_body: bytes, signature_header: str, secret: str) -> bool:
    """Return True if the X-Webhook-Signature header matches the expected HMAC."""
    if not signature_header.startswith("sha256="):
        return False
    received = signature_header.split("=", 1)[1]
    expected = hmac.new(
        secret.encode("utf-8"),
        raw_body,
        hashlib.sha256,
    ).hexdigest()
    return hmac.compare_digest(received, expected)

Rate limits

Scope Rate Header
api_key 1000 / hour All API-key responses include X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset.
auth 10 / min login / register / accept-invitation throttle (per-IP).
api_default 200 / min Reserved (not currently applied — for future scoping).
api_heavy 30 / min Reserved (not currently applied — for future scoping).

When a request exceeds the per-key bucket, CRM returns HTTP 429 Too Many Requests with a Retry-After header. The recommended strategy is exponential backoff with jitter: 

import time
import requests

def call_with_backoff(url, headers, max_retries=5):
    for attempt in range(max_retries):
        r = requests.get(url, headers=headers)
        if r.status_code != 429:
            return r
        retry_after = int(r.headers.get("Retry-After", 2 ** attempt))
        time.sleep(retry_after)
    raise RuntimeError("Rate limit exceeded after retries")

Error codes

Status Meaning What to do
200 OK Success. —
201 Created Resource created. Read the response body for the new object.
204 No Content Success, no body. —
400 Bad Request Validation error. Read the response body's detail or per-field errors.
401 Unauthorized Missing or invalid API key. Verify the Authorization: Api-Key ... header.
403 Forbidden Insufficient role permissions. Check the key's role; ask an admin for a higher role.
404 Not Found Resource doesn't exist. Verify the ID and that it belongs to your tenant.
409 Conflict State conflict (e.g. duplicate name). Read the response body for context.
422 Unprocessable Entity Semantic validation failure. Per-field errors in the response body.
429 Too Many Requests Rate limited. Sleep and retry per the Retry-After header.
500 Internal Server Error Server-side issue. Retry; if persistent, contact support.

Postman / Insomnia collection

CRM publishes its OpenAPI 3.0 spec at /api/schema/. Import the URL into Postman or Insomnia and you'll get a pre-built collection with every endpoint, ready to authorize with your API key.

Full reference

For the complete interactive endpoint list, see /api/docs/ (Swagger UI). Click the "Authorize" button there, pick the ApiKeyAuth scheme, and paste an API key to make live calls right from the browser.
