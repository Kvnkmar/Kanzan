Workflow

Control how ticket assignments and status transitions behave

Auto-transition on assignment When enabled, assigning a ticket in the default "Open" status automatically moves it to "In Progress".
Auto-send ticket confirmation email When enabled, CRM emails the contact automatically as soon as a ticket is created from an inbound email. When disabled, agents trigger the confirmation manually from the ticket page.
Auto-assign inbound-email tickets to Agents When enabled, tickets created from inbound customer emails are routed to the Agent (role: Agent) with the fewest open tickets, ties broken by least-recently-assigned. Offline agents are skipped. When disabled, email tickets arrive unassigned and admins/managers triage them manually.
Route inbound email through the Emails triage desk When enabled, new inbound emails are parked in the Emails triage desk (routed to a department, then auto-assigned to an online agent) instead of immediately creating a ticket. When disabled, the legacy auto-create-ticket flow runs unchanged. Run manage.py seed_inbox_hub_defaults first so a default department exists.
Auto-assign parked emails to online agents When enabled (default), each parked email is auto-assigned to an online agent in its routed department using load + fairness. If no agent is online it is held in the queue and assigned the moment one comes online. Disable to leave all parked email for manual claim/assignment.
