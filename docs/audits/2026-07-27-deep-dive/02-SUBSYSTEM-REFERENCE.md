## Tickets / SLA / kanban (`apps/tickets/`, `apps/kanban/`)
- LOC: models 1514 · services 2086 · signals 812 · views 3031 · access 34 · sla 412 · email_service 380 · webhook_service 142 · tasks 1122. **No `apps/kanban/signals.py`** — card sync lives in `tickets/signals.py`.
- **`Ticket`** ~58 fields. Soft-delete via `is_deleted`/`deleted_at`/`deleted_by` + `SoftDeleteTenantManager`. **No `delete()` override** → `.delete()` is a Django hard delete. `save()` (`:591-625`) auto-fills `tenant` from context, `number` via `TicketCounter.next_number` (select_for_update, no-op on SQLite), and backfills `company_id` from the contact. `clean()` (validates assignee ∈ tenant) is **NOT called by `save()`** → `Ticket.objects.create(assignee=<foreign>)` bypasses it.
- **Service layer = 20 public fns**; no `create_ticket()` (creation is serializer-driven in `TicketViewSet.perform_create`). `ALLOWED_TRANSITIONS` (`services.py:472-478`) slug-keyed; `closed=[]` terminal; custom-status slugs unrestricted.
- 🔴 **bulk_update_tickets "delete" HARD-deletes** (`services.py:1364-1369`, `ticket.delete()`) with **no audit / no `deleted_by`**, vs the single-ticket `perform_destroy` (`views.py:2364-2370`) which soft-deletes + is `restore`-able. Delete is Manager-gated (`views.py:1380-1390`); the destructiveness/audit gap remains. (Pre-73dfef1; MEMORY's "bulk-delete soft-deletes" describes origin — wrong here.)
- 🟠 **`bulk_action` skips `get_queryset()`** — targets `Ticket.objects.filter(id__in=…)` (`views.py:1392`), so the agent row filter is not applied → an agent with `ticket.update` can assign/change-status/etc. on any ticket in the tenant.
- 🟠 **`change_ticket_status` does NOT validate** (`services.py:585`, no `validate_status_transition` call). Kanban `move_card` (`kanban/services.py:253`) and bulk "change_status" (`services.py:1344`) therefore **bypass `ALLOWED_TRANSITIONS`**. Validated surfaces: `change-status` action, `perform_update`, `close_ticket`, `apply_macro`.
- **Kanban sync footguns:** `sync_kanban_card_on_status_change` picks `Column.filter(board,status=…).first()` (lowest order) → on a board with >1 column per status, a drop into the 2nd is silently relocated to the 1st. Pipeline variant matches `name__iexact` → renaming a column breaks that sync.
- `remove_kanban_cards_on_ticket_delete` is **post_delete only** → soft-deleted tickets leave `CardPosition` rows, BUT the board-detail serializer hides them (resolves via `SoftDeleteTenantManager`); the summary `ColumnSerializer.get_card_count` uses raw `obj.cards.count()` → **per-column counts inflated by ghost cards** of soft-deleted tickets (the real residual).
- `fire_ticket_assigned_signal` fires only when `update_fields` contains `"assignee"` (`signals.py:162-163`) → an out-of-band full `.save()` reassignment sends no notification. `assign_ticket` includes it, so the API path is safe.
- `fire_webhooks` uses **`.delay()` not `on_commit`** (`webhook_service.py:141-142`) → a rolled-back txn still fires the webhook. `crm_webhooks` queue is consumed but **producerless** (`apps/billing/tasks.py` doesn't exist); ticket webhooks fall to `crm_default`.
- `escalate_ticket` `escalation_count = (…or 0)+1` (`services.py:1008`) — in-memory read-modify-write, no `F()` → lost update under concurrency.
- **`access.py::agent_visible_tickets_q` = `Q(assignee=user)|Q(created_by=user)`** — a creator KEEPS the ticket after handing it off. `views.py:576-579` carries a **STALE comment** describing the OLD reversed rule. The row filter is inside `if membership and hierarchy_level>20:` → skipped when membership is None (part of the cross-tenant read surface).
- **SLA:** `get_effective_elapsed_minutes` (`sla.py:204-232`) **DOES honour `policy.business_hours_only`** and is live (called by breach tasks). 🟠 `initialize_sla` (`services.py:154-190`) seeds deadlines with `add_business_minutes` **unconditionally** — for a `business_hours_only=False` policy the seeded deadline and the elapsed comparison use different clocks. Fallback = 24/7 wall-clock when no `BusinessHours`. Hub SLA is separate + wall-clock only.
- **Outbound `send_ticket_email`** (`email_service.py:171-257`) sends **synchronously** (`:236`) and records the `out:` threading `InboundEmail` row **only after** a successful send → a send failure leaves no threading anchor.

## Inbox Hub + email pipeline (`apps/inbox_hub/`, `apps/inbound_email/`, `apps/notifications/`, `apps/agents/`)
- **The seam** (`inbound_email/services.py:355-366`): existing-ticket reply → `_add_reply_to_ticket` (always); else `inbox_hub_enabled` → `park_email_in_hub`; else `_create_ticket_from_email`. The local `settings = getattr(tenant,"settings",None)` is a **readability-only** name-shadow (no module-level `from django.conf import settings`; Django settings imported locally as `dj_settings`).
- `HubEmail`: **9 states**, **4 priorities (no medium)**, `ACTIVE_SLA_STATES` = 5 (kept in lockstep with partial index `ih_email_active_sla_due`). 8 inbox_hub models; seeded-but-unused: `DepartmentMembership.skills`, `HubEmail.tags`/`pause_started_at`/`total_pause_seconds`, `HubEmailSLA.escalation_minutes`, `QueueRouting.leave_unassigned_when_no_match`. `Reason.ESCALATION` never emitted.
- **State machine:** `convert_to_ticket` + `dismiss_hub_email` assert against a `select_for_update` locked re-read (concurrency-safe); `reassign_hub_email` + engine `assign_to` also lock. `transition_hub_email` + `escalate_hub_email` read **unlocked** state → 🐛 residual lost-update + state-stomp (escalate `escalation_count` has no `F()`, no lock). `select_for_update` is a **no-op on SQLite** — only serializes on prod Postgres. `escalate_hub_email` is a full no-op unless `can_transition(old, ESCALATED)`.
- **`first_responded_at`** stamped by: convert; transition into a RESPONSE_STATE; reassign/claim only when `actor.pk == new_user.pk` (responder claiming). NOT by manager-routing, engine `assign_to`, or dismiss. SLA sweep treats `first_responded_at IS NOT NULL` as "responded"; `?sla_risk=true` lens filters `first_responded_at__isnull=True`.
- 🔴 `reassign_hub_email` **service has no membership check** — only the view's `_require_member` gates it; `AssignSerializer.assignee_id` uses `queryset=User.objects.all()` (global). Defense-in-depth gap.
- **AssignmentEngine:** `_candidate_user_ids` no-dept fallback uses **raw `role__hierarchy_level==30`** (`assignment.py:246`). `assign_to` stamps the InboundEmail handoff (`assignee`/`inbox_status=PENDING`/`is_read=False`), NOT `first_responded_at`.
- **Access is DEPARTMENT-scoped** (`inbox_hub/access.py`): Admin/Manager (≤20) always; Viewer (>30) never; agent-tier iff (member of ≥1 active dept) OR (tenant has 0 active depts → fall-open) OR (has ≥1 assigned HubEmail). `hub_rows_q` = `(state=NEW AND (dept∈mine OR dept IS NULL)) OR assignee=me`.
- **SLA sweep** `check_hub_sla_breaches` (Beat 120s, `.unscoped`): flags response breach + auto-escalates; one-shot warning (dedup via `auto_classification_data["sla_warning_sent"]`, `HUB_SLA_WARNING_MINUTES` default 15); resolution breach flag-only.
- **Legacy auto-assign:** `auto_assign_ticket` + `get_available_agent` are **DEAD** (zero real callers). Live path = `pick_email_agent`/`auto_assign_email_ticket` (gated by `auto_assign_inbound_email_tickets`, default False) — uses raw role==30, gates on `!=OFFLINE` (not `is_assignable`), fail-open for agents with no `AgentAvailability`.
- **Presence:** `is_assignable` = ONLINE + capacity + `presence_fresh` (last_seen within TTL 90s) + within working hours (**server-local tz**). `touch_presence` auto-promotes OFFLINE→ONLINE; `reap_stale_presence` (Beat 60s) flips stale ONLINE→AWAY.
- Confirmation email (Feature C): `_create_ticket_from_email` sends only if `auto_send_ticket_created_email` explicitly True (default False; inverted guard).
- Inbound attachments: `stream_attachment` inline for raster only (SVG excluded), else forced download, always `X-Content-Type-Options: nosniff`; bad index → Http404. IMAP dedup per (tenant, message_id); 🐛 dedups on `tenant=None` when unresolvable (InboundEmail is NOT TenantScoped, plain manager). `get_system_user` raises on an empty tenant → whole inbound pipeline rolls back + retries.
- api_views legacy create-ticket branch **500s on config errors** (only the hub branch maps ValueError→400).
